## 从参考材料得到的设计判断

用户提供的真机截图是问题证据：抽屉文字与行距偏大、常用入口靠后；账目导航像筛选按钮；账户成为纵向文本长表；账户弹层首屏找不到保存；长分类菜单遮挡页面；导入将大量常规记录和例外政策一起呈现。V11 HTML 用于理解纸张、层次、标题与主题源色，V8/V8.20 用于对照主题演变；没有将旧 HTML 的业务实现移植进 Android。

查阅以下公开项目/文档的产品说明和交互资料，结合提供的截图作判断。没有声称安装、实机体验或逐屏验证这些第三方应用，也没有复制其图像资产：

- [Operit](https://github.com/Adrianh31/operit)：结合用户截图，借鉴当前页面仍然可见、前后平面有透视关系的空间模型。
- [Ivy Wallet](https://github.com/Ivy-Apps/ivy-wallet)：用月支出、收入、余额和近期流水组织日常问题，避免首页只堆入口。
- [Monekin](https://github.com/enrique-lozano/Monekin) 与 [账户层次讨论](https://github.com/enrique-lozano/Monekin/discussions/297)：账户需要可扫描的层次；采用横向摘要卡与独立完整账户页。
- [Cashew](https://github.com/jameskokoska/Cashew/releases)：参考其日期、筛选、分类层级和编辑可达性的产品演进，统一搜索选择器与日历入口。
- [Actual Budget 导入文档](https://actualbudget.org/docs/transactions/importing/)：借鉴先映射、再核对的分阶段心智；保留 Life OS 已验证的本机导入规则。
- [Vico](https://github.com/patrykandpatrick/vico)：评估后未引入。当前需求是两组柱与分类环/条形，用小型 Compose Canvas 展示已有 projection 的结果即可；币种、归属、精确金额仍由现有 Finance 负责。
- [Android NotificationListenerService](https://developer.android.com/reference/android/service/notification/NotificationListenerService)：区分系统授权与 listener 实际连接；提供显式重新连接入口。

## 功能页

四种样式在「设置与主题」中选择，并沿用已有 DataStore 外观偏好：

| 样式 | 空间关系 |
| --- | --- |
| 透视书页 DECK | 当前页面向右平移、绕 Y 轴转动、轻微倾斜；功能页带反向透视和视差 |
| 柔和叠页 LAYERED | 当前页缩小并带阴影，功能页轻微视差 |
| 透光浮层 GLASS | 功能页作为有色透明渐变的前层滑入，当前页只小幅位移；没有使用昂贵的实时模糊 |
| 轻快推页 FLAT | 两页相邻平移，不使用缩放/透视阴影 |

现有 LAYERED/FLAT 存储值仍有效。减少动态效果时使用无动画的 FLAT 呈现。主内容始终是同一棵已挂载导航树；打开抽屉不切换业务路由。

手势同时使用方向意图、速度和进度：慢拖约 22% 揭露行程即可提交；短促横向 flick 可以提交；保留左右 24dp 系统边缘区域。读取子手势的消耗状态，竖向意图让给列表。中途取消恢复开始状态。

两列列表改为稳定键与 contentType 的 LazyColumn，缓存排列与成对数据；进度读取放入 graphicsLayer，避免逐帧重组整个列表；主题解析按源色缓存并提前结束已满足对比度的调整循环。这些是代码审查发现的工作量来源与对应优化，并非经过真机 profiler 确认的唯一掉帧原因。

UI 改用平台无衬线字体及真实字重，正文 14sp，功能入口 13sp，少量标题保留克制的衬线字体。入口至少 48dp 高，图标 19dp、统一圆角细描边；重新整理若干识别度较差的路径。无新增图标库。

默认前六项为记一下、账目、日历、衣橱、收件匣、计划。长按任意入口或点「整理」进入排序：长按拖动、边缘自动滚动，也可用上下按钮；保存后前六项成为常用区，其余按保存顺序排列。仅存稳定 module ID 的展示顺序；未知 ID 忽略，新模块追加，不改变模块身份/路由。恢复默认需要再保存，退出不保存不影响原顺序。

## 五色主题

预设的 accent、paper、secondary、soft、warm 均作为语义输入：交互、纸张、冷调表面、选区、暖调余额/提示表面。账户色条与图表用源色形成辨识度，文本所在表面经过对比度约束，金额用等宽数字特性。

自定义主题扩为五字段、五色预览，继续支持未保存预览与取消。旧三字段主题缺少 soft/warm 时分别回退到 secondary/paper，不使旧数据失效。极端自定义源色会被调整为可读的文本/表面；源色本身仍保留。

## 账目日常界面

- 保留模块局部四页：总览、流水、账户、分析，改为有图标和选中态的 NavigationBar；不新增根导航栏。
- 总览：月收支卡、按币种分别计算的账户余额合计、横向账户卡、待确认入口、导入入口、近期流水。待整理到账先显示摘要，按需展开。余额合计使用 BigInteger，不混加不同币种。
- 流水：按日分组，主行显示事由/商户或转账两端；副行分类与账户，右侧金额与时间，相关角色作为补充标签。编辑仍走原 ViewModel/Repository 命令。
- 日期：月标题打开日历，前后月、单日、日期范围、整月、交易日点标；重开保留已选范围。编辑流水只能选择单日，保留时间编辑与原发生时间的保存语义。
- 分类/标签/账户：搜索弹层、固定搜索框、惰性列表、分类父路径、最近选择；分类筛选另显示按实际使用量计算的常用项，支持清除。最近选择仅在当前进程保留；自定义分类/标签仍可输入。
- 分析：最多 12 个连续月的个人收支柱图、分类净支出环图与排行。币种分开；负值以相同比例绘于零线下，环图只包括正向净支出并明确说明退款。月份、分类排行/全部分类可下钻真实流水，环图本身不是交互热点。Canvas 提供金额语义和相邻可点击列表，没有将像素计算写回账目。
- 账户、流水、分配、Proposal、规则的主要保存/确认动作放在弹层底部，固定标题、中部滚动，跳过半展开初始状态，适配 IME。

## 旧账导入

文件 → 账户 → 检查 → 确认。账户映射改为可展开卡片；正常行归入摘要；退款、报销、手续费、重复与不支持项按组检查，明细支持搜索并可查看原记录；最终动作固定在底部。

LegacyLedgerReader 和导入业务策略没有重写。普通行默认选择，重复候选默认跳过；多问题行仍必须满足原有批量政策；退款/报销证据不制造附加资金流。账户起点与现有映射语义、导入确认、批次撤销保护保持原样。用户提供的 4548 行结果是参考证据，本轮没有得到该工作簿并重跑它。

## 支付发现：已修复的可诊断性与未知根因

确认存在的代码问题：以前多个分支直接返回；只读单一正文来源、支付标题匹配较窄，无法区分“未收到通知”与“收到但拒绝”。现版记录每个阶段的结果，合并 BIG_TEXT/TEXT/TEXT_LINES 的非空去重内容，并允许带支付结构证据的普通应用标题。移除了通知已送达后再查安装状态的冗余门槛。

**不能据此认定用户手机的真实根因已经找到。** Manifest 本来已有来源包 queries，不能把包可见性推断为已证实故障。没有该手机的通知原文、listener 状态或付款重现，不能保证所有微信/支付宝版本的模板已覆盖。

诊断页区分授权/连接、总开关、来源开关，分别显示两种来源最近收到时间、结果、可安全识别的金额和待确认入口。结果包括收到、总开关关闭、来源关闭、分组摘要、非支付、未完成/推广、无金额、多金额、方向不明、重复、过期、保存失败、格式异常、已创建 Proposal。新通知序号阻止较早异步结果覆盖较新通知状态。

诊断只保留当前进程两种来源最近的时间、枚举结果、金额与 Proposal ID，可一键清除，不保留诊断标题、正文或商户。合法 Proposal 的既有证据与生命周期不变。后台确认提醒发送失败不会伪装为 Proposal 保存失败。重复/过期由 Repository 事务返回明确结果。

保守解析仍拒绝非来源包、聊天式普通标题、失败/待支付、无明确方向与无有效金额；支持 ￥/¥/元/CNY/RMB、千分位和精确最小货币单位。多个金额时 Proposal 的金额保持空白，要求手填，不猜余额/折扣。不使用 Accessibility、浮窗、云端或 AI；不直接写入 Truth。

# Life OS · Companion AI / Agent / Tool / Skill PRD v0.1 FINAL

- **需求状态**：CONFIRMED（产品交互与权限原则）；技术选型、性能指标及开源代码复用另行评审。
- **阶段**：需求设计；不授权开始代码开发、部署或更改 Ombre Brain 仓库。
- **范围**：Life OS 的 Companion AI 自主程度、生活数据工具、任务执行、Skill 组织、确认与审计，以及与已有 Ombre Brain 的接口边界。
- **依据**：Owner 在当前产品讨论中的确认；已检查 `cnsj-123/vps-` 的 `feature/gateway-v2` 部分关键文件。当前仓库检查不是全面代码审计，分支仍可能继续变化。

## 1. 定位与目标

Companion AI 是 Life OS 中自然交流的伙伴，不是要求用户输入固定命令的数据库控制台。AI 能理解聊天语境，必要时自主使用已授权的查询能力；对于用户交代的复杂整理工作，在授权范围内一次执行完整流程；对正式数据变更统一给出可理解、可修改的结果，让用户最终确认。

**核心原则：过程自主，结果确认，尽量不打断聊天。**

- 自然语言表达即有效入口，不要求用户主动说“请调用某工具”或“新增某模块记录”。
- AI 可以判断某条日常信息值得记录，主动提出候选；不为展示工具能力而检索或弹窗。
- 已授权的普通读取与中间计算不逐步确认。敏感数据仍受单独授权规则限制。
- 正式向 Life OS 写入、修改或删除记录时必须由用户确认；多记录任务允许汇总确认和逐项调整。
- 不因识别到生活信息而强迫用户补齐所有字段，也不因信息不足捏造事实。
- AI 不擅自安排活动、创建任务、消费、对外发布或持续催促。

## 2. 与既有系统的边界

| 系统 | 职责 | 不承担的职责 |
|---|---|---|
| Life OS 客户端 | 完整聊天记录及附件、生活事实数据库、呈现候选和确认、各模块视图、用户授权、同步恢复 | 不独立重造 Ombre Brain 长期记忆系统 |
| Life OS Domain API | 统一事实与跨模块关联、受控查询、提案预览、变更应用、撤销与历史 | 不因 AI 要求而绕开正式写入规则 |
| Ombre Brain 记忆层 | 记忆留存、检索、浮现、相关召回及原有生命周期、You/Them 等 | 不充当 Life OS 财务、衣橱或旅行事实数据库 |
| Ombre Brain Context Gateway | 请求规范化、上下文装配与权限边界内的注入、模型/上游连接、已有缓存及召回传输机制 | 不独占完整聊天历史，不直接承担整个 Life OS 数据模型 |
| Companion AI | 自然对话、合理选择已授权工具、提出生活记录候选、统筹被交付的任务 | 不越权操作、不凭记忆直接写入生活事实 |
| 后台工作模型 | OCR、图像理解、抽取、去重、分类、草稿生成等批处理 | 不必以 Companion 人格运行，不自动获得更多权限 |

**现有代码观察（仅已检查的 `feature/gateway-v2`）**：`src/web/gateway.py` 委托 `context_pipeline_coordinator.py`；有 Operit Anthropic Messages Adapter；Provider-bound Live Recall Transport 将请求附加到 Anthropic MCP Connector，默认关闭；有些阶段明确为 shadow-only。产品设计不得把实验功能写成已上线能力。

## 3. Tool、Skill、Agent 的含义

### 3.1 Tool：原子能力

- 定义明确的操作、输入/输出 Schema、权限范围、读写性质、用户身份与来源校验、审计方式。
- 示例：`life.search_records`、`life.get_event`、`life.find_related_purchase`、`life.prepare_record_proposal`、`life.apply_confirmed_changes`。
- Tool 不能直接继承模型所有可见数据的权限；工具调用必须由服务端重新验证授权。
- 工具描述与外部输入均不被视为更高优先级指令。

### 3.2 Skill：可复用的专业工作法

- Skill 说明完成某类任务的流程，可以组合多个 Tool、提示词、校验规则、参考资料或脚本。
- 首批候选：截图资料整理、购物信息抽取、旅行记录梳理、日常事件转记录候选、个人作品集导出候选。
- 需要时才加载匹配的 Skill；不把全部专业说明放入每一轮 Companion 对话。
- Skill 不具有独立授权；即使 Skill 描述要求调用某工具，也不能突破用户模块权限、媒体可见性和 Creative Vault 隔离。

### 3.3 Agent：多步骤任务执行能力

- 在一次用户委托或自然对话形成的合理任务范围内，规划并完成所需步骤。
- 可以使用多个已授权 Tool / Skill；后台工作模型可独立承担长耗时解析。
- 中间工作不逐步打断用户；必要时可显示折叠进度和取消入口。
- 结果需要正式生效时，统一进入候选审查；批准后仅执行批准的变更。
- 不因启动了某个 Agent 就获得跨模块无限读取、越权写入或主动长期运行权限。

## 4. 自然对话与自主读取

### 4.1 允许的默认行为

当对应模块和数据已授权 AI 访问时，Companion 可在确有上下文价值时主动调用查询工具，例如用户问“我上次去 KTV 是什么时候”，直接读取 Hobbies 中的真实事件并回答。

聊天中的工具轨迹默认折叠，可按需查看。无需用户确认每一次已授权的普通只读调用，也不强迫用户记忆内部工具名。

### 4.2 限制

- 仅检索回答所需的最小数据；结果必须与当前话题有关。
- 模块权限为“询问”或“拒绝”时不能靠后台任务或 Skill 绕过。
- Finance / Health 等敏感数据遵循既定模块和记录级 AI 权限；一般只读工具获准不等于全部敏感信息均获准。
- 不得为了优化效果擅自将 Life OS 数据交给未获准的外部模型、Skill 或第三方 MCP 服务。
- 查询结果保留出处及事实时间语义；不能把计划、候选、预测冒充既成事实。

## 5. 自然聊天产生记录候选

**典型场景：** 用户随口说“我打算下个月去看演唱会，已经买好票了”。

1. Companion 正常继续聊天；若记录有价值，可在权限内搜索现有 Hobbies、Plans、Shopping 或已存在的票务/财务记录。
2. 若找不到对应记录，生成“演唱会计划”候选；演唱会日期、艺人、场馆等未明确的信息标为待补充。
3. “已经买好票”可以成为票务状态信息，但**不能**据此捏造付款金额或新建财务流水；只有找到对应真实交易才建立关联。
4. 在自然聊天的合适时机弹出一张简洁候选卡，允许查看、修改、确认、稍后处理或忽略。
5. 用户确认后才写入 Life OS；跨模块关联按统一事实系统自动同步。

**候选 ≠ 正式事实**。如果只说“计划去”，不能计为已参加、已完成或真实穿戴/消费事件。

## 6. 批量任务与一次性确认

**典型场景：** 用户发几十张评论截图，要求整理讨论内容并保存到 Knowledge。

- 在当前已授权的数据范围内，后台连续完成 OCR、来源识别、主题拆分、观点整理、去重、保留不同意见、生成可编辑知识稿；保留原截图与可追溯来源。
- 不因每一步完成而连续弹窗或要求新的形式化指令；长任务可以显示折叠进度、取消与出错摘要。
- 仅当确实缺失影响继续执行的必要条件、需要新的敏感授权、存在无法合理选择的实质分歧时，才中途询问。
- 完成后统一展示摘要与候选变更清单。用户可一次确认全部、逐项修改、去除部分、稍后处理或放弃。
- 对确认后的记录执行一次受约束的提交；未确认项不正式入库。
- 重试与恢复不能导致重复记录、重复扣次、重复写入或重复关联。

**交互要求**：正常完成的批量任务不应展示逐条确认轰炸；确认界面应当支持整体浏览并展开细项。

## 7. 写入批准与权限边界

### 7.1 两种不同的确认

- **数据访问授权**：决定 AI 是否可以接触指定模块、记录、媒体或敏感字段；沿用模块与记录级允许／询问／拒绝，以及一次、当前对话、持续等既定授权范围。
- **正式变更批准**：决定具体候选是否写入 Life OS。即使 AI 拥有读取授权，也不能自动获得正式修改权限。

### 7.2 所有正式 Life OS 变更必须确认

- 新建、修改、删除、关联变更和可能引发连锁业务后果的操作都生成待确认内容。
- 一次任务可批量批准多项，避免多次弹窗；必须能够查看影响范围和逐项修改。
- 变更预览展示关键共享字段、专业字段及主要联动后果，例如会员扣次、日历日期和生活统计。
- 用户确认后，后端按确认的提案及版本重新校验权限、当前值与冲突；不能用前端“已确认”标志代替服务端鉴权。
- 若确认前数据已变化，显示当前值与提案值供用户选择，不静默覆盖。
- 保存历史并提供适当撤销；若撤销会涉及真实外部动作，不能假称可撤回。

**注意**：此处“所有写入必须确认”特指 Life OS 正式生活数据库。Ombre Brain 自身的记忆写入和生命周期遵循既有记忆策略与工具权限，不在本 PRD 中擅自改为同一套卡片确认。

### 7.3 外部动作

对外发送、下单、付款、跨应用修改、系统权限变更等高影响操作不因聊天授权而默认自动执行；未来另设明确的用户授权与执行验收规范。本期不把通用手机自动化纳入默认 Agent 权限。

## 8. AI 主动性

- 允许 Companion 在相关话题中自然提起经授权的长期记忆和生活记录，必要时提出合理候选。
- 不自动创造目标、任务或提醒，也不因“很久没做某事”不断催促。
- 主动信息应与当前话题和真实数据有关；已经拒绝或忽略的候选不反复提示。
- 用户说“稍后处理”进入统一草稿箱；“忽略”不进入日常待办和提醒流，不自动等同于删除原始证据。
- 后台已被用户启用的定期识别或备份可按各自 PRD 工作，但不赋予 Companion 额外的主动行动权。

## 9. Creative Vault：绝对隔离

- Creative Vault 的内容、标题、媒体、关联、搜索索引、嵌入向量及元数据均不暴露给普通 AI、Gateway 上下文流水线、Skill、Agent、普通 MCP Tool、审计检索或推荐引擎。
- Creative Vault 自有独立的本地非 AI 搜索与加密同步，不出现在普通候选、聊天分享、统一作品集或生活数据工具清单里。
- 不能通过“用户已经允许查询其他模块”“Agent 是后台执行”“Skill 内部脚本”“工具输出”间接进入 Creative Vault。
- 后续若设计 Vault 独立的本地非 AI 导出，走独立流程，不能误写成 Companion 的直接权限。

## 10. 工程边界、异常与可观测性要求

- 模型判断不能替代服务端权限、正式记录数据校验、幂等和冲突检查。
- 截图、网页、评论、OCR 内容及外部工具返回值属于不可信输入，不得把其中的伪指令升级成工具调用权限。
- 每个任务有任务 ID、受控权限快照、已执行步骤和结果状态；重启和网络失败后可以安全恢复或告知失败。
- 任务不能无限循环或无上限消耗模型预算；具体并发、次数、Token、媒体大小和超时在技术设计阶段确定。
- 对用户提供可理解的结果、错误和必要操作历史，审计记录最小化；敏感正文、令牌、完整对话不进入普通运行日志。
- 能取消仍在运行的任务；取消不等于撤回已经完成的外部不可逆动作。
- 不把候选中间结果冒充成功保存；不能把仅在 shadow-only 阶段观测到的能力当成正式可用功能。

## 11. 典型验收场景

| 场景 | 预期 |
|---|---|
| 已授权 Hobbies，用户询问上次 KTV 日期 | 自动查询并自然回答；不要求逐工具确认 |
| Companion 认为可帮助但不需要历史数据 | 正常聊天，不额外检索或弹窗 |
| 用户提到已买下个月演唱会门票 | 可生成未完成的演唱会计划候选；没有真实交易不得新建金额 |
| 用户确认演唱会候选 | 仅确认后的记录生效；关联模块共享同一事实 |
| 用户上传几十张截图要求整理 | 一次执行 OCR→分类→合并→草稿；完成后统一审阅 |
| 批量候选中只有一部分需要保存 | 可逐项取消/修改，保存选中项而不是要求重做任务 |
| 重新提交、任务重试或网络断线 | 不重复新增记录或触发重复联动 |
| 无敏感模块授权 | 该模块不能经 Tool/Skill/Agent/其他模块引用越权访问 |
| 读取权限已允许但要修改历史日期 | 仍展示变更确认和受影响模块；确认后统一更新 |
| Creative Vault 内容存在 | AI 工具列表、全局索引、上下文和后台处理均不可见 |

## 13. 后续技术设计与实施前置条件

1. 核验 Ombre Brain 实际集成基线与各实验开关，列出已验证功能、待测试功能和尚未实现的部分。
2. 定义 Life OS Domain API 的读写 Schema、提案结构、幂等键、版本冲突、审计及撤销协议。
3. 定义前端批量确认卡、折叠进度、草稿回流、权限提示与任务恢复交互。
4. 逐项目审查开源框架的真实适用范围、依赖成本、许可证及安全边界，然后选择最小必要组件。
5. 经过 Owner 审核后再拆 Codex 实现任务；不因 PRD 标注 FINAL 而自动授权开发。

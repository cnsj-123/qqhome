# Life OS 领域归属注册表

## 1. 文档目的

本文是 Life OS Architecture v0.1 的**完整 Domain Ownership Registry**。

它回答：

> 每一类 Canonical 事实，究竟归谁拥有？

原则：

> **One Canonical Type, One Owner。**

`04-领域归属与跨模块共享.md` 负责 Ownership 原则与典型示例；本文负责**完整列表**。

---

## 2. “UI 模块”和“数据 Domain”不是同一概念

- **UI 模块 / Surface**：负责呈现、入口、聚合与交互，通常**不拥有**第二份业务 Truth。
- **数据 Domain**：Canonical Fact 的语义 Owner，负责语义定义、写入规则、invariant、merge / deletion / conflict policy、schema evolution。

注册表因此分三类组织：

```text
A. Canonical Business Domains
B. Projection / Intake / Platform Surfaces
C. Infrastructure / Separate Systems
```

### Membership


### Food


### Hobbies


```text
Owns:
- PlantCategory
```

说明：用户实际拥有的植物是 `Item` + Garden specialization / extension，**不是**第二个 physical identity（见 `01-世界模型与核心数据语义.md` §24.1）。

### Health

```text
Owns:
- SleepEvent
- MenstrualEpisode
- MedicalVisit
- MedicationProfile（长期药品档案 / Medication identity）
- MedicationIntake（服药 Event）
- HealthObservation
- BowelMovement
```

说明：`MedicationProfile` 与 `MedicationIntake` 分开；归档药品不能删除过去的服药记录。

### Reading

```text
Owns:
- ReadingWork / Book identity
- ReadingSession
- Me ↔ Work ReadingState
```

说明：阅读状态属于 Relationship State，不是作品本体的全局属性。

### Travel

```text
Owns:
- Trip
- TravelLeg
- HotelStay
```

### Place / Core Location

```text
Owns:
- spatial Place identity
- GenericVisit only when no professional Event exists
```

说明：Place 只表示空间位置意义的地点；纯线上店铺不伪装成 Place。

### Plans

```text
Owns:
- Goal
- Project
- Task
- PlannedEvent
- RecurringPlan
```

### Knowledge

```text

```

### Skincare

```text
Owns:
- SkincareSession
```

说明：它来自已确认 Life Marks PRD 的“护肤是专业子模块”要求。本轮只确认数据 Ownership，不新增 UI PRD、不扩展功能范围。

## 4. B. Projection / Intake / Platform Surfaces

以下 Surface **明确不拥有第二份业务 Truth**：

```text
Home
Calendar
Search
Life Marks
Capture
Media Library
Share & Export / Portfolio
Companion Chat
Map / Place projection surfaces
```

- 它们读取 Canonical Data，生成 View / Candidate / 入口。
- 它们可以生成 Proposal，但不能成为新的 Domain Truth。
- **Capture 是 Intake，不是 Session Owner**：计时等 Session 归属目标 Domain（见 `03-命令流与查询流.md` §14.1）。

---

## 5. C. Infrastructure / Separate Systems

```text
Control Plane
Sync / Backup / Recovery
Ombre Brain
Context Gateway
Conversation Archive
Creative Vault Secure World
```

- 它们提供平台能力或独立安全域，不属于任何业务 Domain。
- **Conversation Archive 不是 Domain Truth**：它属于 Durable User Content，必须支持同步 / 备份 / 恢复。
- **Creative Vault Secure World** 是独立安全域（Vault ciphertext domain），不是普通世界的一个 `private=true` 子对象。

## 6. Domain Contract 模板

每个 Domain 后续统一使用同一 Contract 结构：

```text
Owns:
References:
Accepts Proposals From:
Emits:
Consumes:
Deletion Policy:
Merge Policy:
Conflict Policy:
```

### 示例：Hobbies Domain

```text
Owns:
Interest
HobbyTopic
HobbySession
ClassSession
ConcertEvent
Artwork

References:
Person
Place
Membership
Transaction
MediaAsset

Accepts Proposals From:
Companion
Capture
Import
Calendar

Emits:
SessionCreated
ArtworkUpdated

Consumes:
(授权范围内的事件与 Proposal)

Deletion Policy:
不盲级联删除；保留历史关系

Merge Policy:
Entity Resolution 允许提出 Merge Proposal，不自动合并

Conflict Policy:
语义冲突保留为 Conflict Proposal，不静默覆盖
```

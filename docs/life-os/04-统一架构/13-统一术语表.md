# Life OS 统一术语表

## 1. 文档目的

本文是 Life OS Architecture v0.1 的**统一术语基线**。

它负责统一 PRD、架构、数据模型与 UI 文案之间对同一概念的说法，避免同一对象出现多个名字，或同名指代不同对象。

本文只统一**术语与边界**，不新增产品需求。

---

## 2. 正式术语映射

| 中文说法 | 正式术语 | 说明 |
|---|---|---|
| 正式事实 | **Canonical Truth / Canonical Fact** | 已被正式接受的 Canonical 状态 |
| 候选 / 提案 | **Proposal** | 尚未 Commit 的 Canonical Change Plan；Capture 中的 Candidate 统一映射为 Proposal |
| 草稿 | **Draft** | 仅指用户尚未完成的内容，例如未完成文章、Plog、Composition；**不得**等同于“稍后处理的 AI 候选” |
| 稍后处理的候选 | **Proposal.status = SNOOZED** | 通过 **Inbox** 展示，不是 Draft，也不是 Canonical 数据类型 |
| Inbox | **Inbox Surface** | 注意力 / 暂存 Surface，不是 Canonical 数据类型 |
| 证据 | **Evidence** | 我们为什么知道这件事 |
| 机器抽取 | **Extraction** | 从 Evidence 机器提取的结构化信息，属于 Derived |
| 派生数据 | **Derived Data** | 可重建；必须继承源数据隐私与访问限制 |
| 商品 | **Product** | 外部世界中的商品概念 |
| 用户实际拥有的某一件实物 | **Item** | 唯一的 canonical physical identity |
| 购买行为 | **Purchase** | 购买事实（业务事件） |
| 真实资金流 | **Transaction** | 钱发生了什么变化 |
| 计划 | **Intent** | 准备发生，但尚未发生 |
| 已发生 | **Event** | 实际发生了什么 |
| 媒体身份 | **MediaAsset** | 全局共享的媒体对象身份 |
| 媒体位置 | **Locator** | URI / path / cloud URL / hash 等定位信息 |
| 地点 | **Place** | 具有空间位置意义的 Entity |
| 品牌 / 商家组织 | **Organization / Merchant Role** | 线上店铺通过它表达，而不是 Place |
| 完整聊天历史 | **Conversation Archive** | Durable User Content，不是 Canonical Life Truth |
| AI 长期记忆 | **Ombre Memory** | AI 的长期记忆 / 关系记忆 / 召回 |
| 单轮模型上下文 | **Model Context** | 每轮临时组装的上下文 |
| 排版工程 | **Composition Project** | 引用已有内容，不复制事实（PlogProject 即其一） |
| 导出成品 | **Render / Export Output** | Composition 的输出结果，可重建 |

---

## 3. 必须突出的不等式

以下对象在架构中**永远不相等**，工程与文档都不得混用：

```text
Product ≠ Item ≠ Purchase ≠ Transaction

Proposal ≠ Draft

Intent ≠ Event

Evidence ≠ Extraction ≠ Proposal ≠ Truth

Conversation Archive ≠ Ombre Memory ≠ Model Context

MediaAsset ≠ Locator

Composition ≠ Render
```

补充强调：

- **Proposal ≠ Draft ≠ Inbox ≠ Truth**
- **MedicationProfile ≠ MedicationIntake**
- **Online Merchant ≠ Spatial Place**

---

## 4. 术语使用规则

1. 同一概念只使用本表正式术语，不在不同文档中另起别名。
2. 中文说法仅作为解释，不替代正式术语。
3. 稳定技术词（Life OS、Ombre Brain、API、AI、Agent、Plugin、MCP、Room、SQLite、Sync、Backup、Event、Entity、Proposal、Truth、Derived、ChangeSet）保留英文。
4. 若某个术语的含义需要改变，必须通过正式 ADR 记录，而不是在单个文档中悄悄改义。
